# 语音链路调整与验证

此次按用户要求移除说话人限制，优先修复唤醒和采集可靠性。

## 审查结果

1. 原声纹环节确实可能在关键词命中后返回 retry_wake / enrolling / other_speaker，使请求根本不进入云端 ASR。这属于门控拒绝，不等于云端转写错字。
2. 原待机窗口是 3 秒窗口、1 秒步长，本身重叠，没有固定空挡。但有限窗口数、满队列跳过、唤醒切换清空队列都可能丢失信息。
3. 原 5 秒硬切会把较长句子拆开，云端逐段独立识别，损失跨片段上下文。
4. 原浏览器同时请求自动增益、噪声抑制与回声消除。代码无法证明它已经处理过度；本次关闭增益与噪声抑制，改用可检查的单层本地降噪。Chrome 自动验证实际 getSettings 返回二者均 false。
5. 真正流式 ASR 主要改善延迟与跨块解码连续性，准确率仍取决于模型、声音与断句；当前完整 WAV 的 chat/completions 输入不能通过 stream=true 自动变成持续音频输入。此次没有更换账户端点、模型或凭据，没有实现 Realtime WebSocket。

## 当前实现

麦克风 → 浏览器回声消除（AGC/NS 关闭）→ 连续 PCM → 重叠唤醒窗 / 自然断句 → 内存队列 → 16kHz 单声道 WAV → 本地温和谱域降噪 → 本地唤醒或已唤醒会话 → 云端转写 → Agent。

- 唤醒窗口 6 秒、步长 1 秒，首次 1.5 秒；关键词阈值从 0.15 调到 0.10。
- 声纹模型不再加载，不再提取参考、注册或匹配说话人。任何人可在已唤醒会话中提出需求。保持 Hi Claude / 既有有限发音变体。
- 分段保留 0.6 秒预录、0.12 秒持续触发、0.9 秒静音结束、25 秒请求上限；不再 5 秒硬切。
- 启动与推理等待使用同一原始 PCM 内存队列，转换在请求准备发送时进行。预算为 120 秒待处理样本（重复的重叠窗也计入）；超限明确提示并停止，避免静默漏录或无限增长。
- 唤醒切换去掉重复窗口，将最后已提交窗口之后的采样按时间位置拼接到对话断句器。测试逐样本验证没有缺口和重复。
- 本地 voice_denoise.py 使用保守谱掩码，削弱低频嗡声和稳定底噪，幅度掩码下限 0.6，避免强抑制造成词头消失；不提高音量，不分离多个说话人。
- 两份证据：input.wav 为接收音频；asr.wav 为降噪后实际送云端的音频。result.json 分别记录哈希。诊断关闭不落盘；开启时仅为会话缓存，结束语音 / 正常退出服务自动清除本服务创建的目录。历史固定样本和监测报告不清除；异常强杀可能留下缓存。
- 新首页与旧媒体工作台共用断句、缓存、麦克风参数及后端，已同步修改。

## 验证与边界

- Node 测试覆盖无声纹唤醒、不同人继续发言、会话过期、会话结束后推理结果不能复活会话、原始与降噪 WAV 对照、缓存清理、跨窗口保全、超过 5 秒完整采集与队列溢出提示。
- Python 测试覆盖降噪的长度、静音、有限数值、低频抑制与语音频段保留，及原关键词发音规则。
- 本地真实模型加载测试使用已有合成 WAV 固定样本，background → waiting_wake，wake → woke，后续三段（包括另一音色）→ accepted。报告 reports/live/voice-identity-live-results.json 不保存音频 Base64。
- 浏览器模拟麦克风测试覆盖新旧页面唤醒与转写、实际麦克风处理参数、文声开始显示同步、会话缓存清理，并回归单次拍照与监测报告。
- 这些结果不代表真实房间中的准确率已达到某一水平。谱域降噪不能移除另一个人的清晰讲话；开启后模型会收到这些声音。
- 当前实际播放和之后约 0.2～0.25 秒仍跳过语音判定，以防自身播报进入请求；尚无语音打断。唤醒词和命令在同一个已提交唤醒片段中时，仍需下一段重复需求。超过 25 秒会拆分为独立请求。
