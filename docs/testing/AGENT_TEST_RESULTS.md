## 真实 API 检查

当前保存的第二个 Key 已通过官方 `/models` 鉴权，返回 `deepseek-flash` 和 `deepseek-v4-pro`。初次出现的 HTTP 401 最终定位为本地解密子进程未正确读取 Key：PowerShell 7 的 PSModulePath 干扰了系统 Windows PowerShell 模块加载，旧读取方式还未拒绝空结果。已改为独立脚本读取、隔离模块路径并拒绝空 Key。不能把此前 401 当作 Key 失效证据。

真实 `deepseek-flash` 已完成工具闭环：模型请求一个工具 → 本地 Agent → 真实 MCP stdio → 本机模拟设备 → 结果回传模型 → 中文最终回答。模拟设备仅返回新建虚构值 `DEMO-ONLY-1.0`，不是设备实际版本。云端只接收通用的 `get_demo_version` 演示工具和虚构数据；不包含项目工具目录、固件样本或真实设备诊断。详见 `reports/live/agent-live-results.json`。

最终复核：1 次工具调用、1 次本地模拟设备查询，模型返回“虚构演示版本为 DEMO-ONLY-1.0”，本轮累计 usage 为 678 Token。日志脱敏保留数值型 Token 指标，隐藏认证 token。

原先计划使用项目固件响应样本的外发测试被自动审批拒绝，未执行；更安全的纯虚构数据方案已获准并通过。尚未进行真实 AI + 实机 T830 查询或写操作。实际交互会把所选工具描述和经过脱敏、压缩的查询结果发送给 DeepSeek。

## 2026-10-12：四项 UBUS 查询的会话恢复修复

针对 devinfo_get、get_status_info、get_ssidPage_info、get_workmode 在持续运行中出现的 Access denied，对照 scripts/smoke.mjs 确认两条入口共用 src/t830.mjs；冒烟脚本新进程启动获得新会话，而持续运行的 Agent 可能继续使用已失效会话。

在设备层补充：原查询与 session/access 都明确返回 RPC -32002 或 UBUS 6 时，仅在 auto/always 模式重新登录一次、携带新 Cookie 重查原工具；恢复后仍失败会再次诊断，确认目标 access=false 且对照 access=true 时停止。诊断失败不会直接宣称固件没有授权。原有单工具最多四次业务请求、一次认证更新和队列边界仍保留。未增加备用 URL、不同设备方法、提权或 Agent 无限制重试。

已新增 13 项回归测试：四个接口 × 两种拒绝码恢复；持续拒绝仍只恢复一次；恢复后真实 ACL 拒绝正确停止；never 模式边界；真实 MCP SDK/stdio 长连接中恢复后四项查询成功；并发 UBUS 调用只进行一次认证更新。全部使用模拟设备，不调用云端模型。

## 2026-10-12：上下文、记忆、任务恢复与工具扩充

- 上下文达到字符预算的 75% 时，按完整问答轮次生成有长度上限的历史摘录，默认保留最近两轮及当前轮；不拆分正在进行的工具调用。摘要是截取的历史证据，不能替代当前设备查询。
