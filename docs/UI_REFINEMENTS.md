# 界面与声音细化

## 页面

- 清理用户列出的页脚、口号、说明性小字和摄像头重复提示。保留打开摄像头的明确确认按钮与用途标题。
- “流量时光”改为“流量统计”。移除图表 + / − / 回到此刻按钮，保留原有滚轮、双指、拖动和键盘操作。
- 时段按钮按时间长短设置宽度和底色深度，选中态独立高亮。演示 / 真实采集标签保留，防止把模拟曲线误当实测。
- 本地连接的光点在移动、淡出后停顿，再开始下一轮；一轮 6.8 秒，不再立即重启。
- 全局字号增大，网络地址值再单独增大。晴空白和雾蓝白使用明显不同的背景、卡片与光晕色调。
- 设置下拉由 Choice.tsx 自绘，使用柔和圆角和浅边界。保存反馈使用 4 秒悬浮提示，不参与文档流；底部仅有未保存更改时显示简短提示。统一保存按钮固定在设置底部，音色、语速和外观一起保存，退出取消草稿。
- 模型回答由 AnswerView.tsx 显示为首句、分区、信息行和要点，避免原样堆 Markdown；文字以 React 文本节点渲染，不执行原始 HTML。
- 设置与模型回答使用 ScrollPane.tsx 的自绘滑轨与滑块，隐藏原生滚动条，支持拖动和键盘。
- 三个查询入口采用 100% / 92% / 84% 宽度、向背景淡化的层次，取消箭头，加入呼吸、扫光和粒子模糊消散轮换。每 8.5 秒轮换，悬停、聚焦、忙碌或页面隐藏时暂停。内容来自 MCP 已开放且不缺必需参数的读工具目录，未开放的能力不出现。

## 对话与声音

- 网页 Agent 增加呈现风格指导：先结论，再必要信息与下一步，减少长表格与接口名堆砌，保留告警、未执行和待确认边界。工具策略、写权限和确认流程沿用原实现。
- 唤醒后，球体读取麦克风 RMS；播放时读取实际输出 PCM 的 RMS，独立于音量滑块；音量设为零仍能感知模型在播报。WebGL 不可用时，CSS 球体也会响应声音。
- 空闲两分钟收起 AI 交互框并回到唤醒待机；实际人声、播报和在途处理避免错误超时。手动收起仅隐藏聊天框，需点击语音关闭按钮才结束语音待机。保留既有非全双工限制，播放期间尚不处理用户语音指令。
- 前端自动播报请求 concise=true：长答复先由媒体模型改写为最多三句的短口语摘要；检查长度、新数值、失败和待确认边界，不合格或摘要服务失败时退回保守的短摘要。短回答直接整理成口语文字。完整答复在声音开始播放时显示，不再把全部屏幕文字逐段朗读。
- 摘要与合成分开。合成模型只逐字朗读确定的摘要，禁止再次改写、添加笑声或语气词；自然口语由摘要内容和停顿承担。
- 语速 0.85～1.20 倍，默认 1.00，步长 0.05。后端 FFmpeg 使用 atempo 校准时长，浏览器按处理后的音频正常播放，不用浏览器变速改变声调。
- 音色为“晴声 · 女声”和“和声 · 男声”。以官方 Cherry / Ethan 为基底，通过轻微音高、频响、动态和峰值控制调校。官方只指定 Cherry 为默认声，Ethan 是本次选择的中文男声基底，并不存在官方“默认男声”。这不是声纹克隆，也不代表复制了 ChatGPT 的专有声音。
- 设置内可试听草稿音色及语速，保存后应用到新合成的音频；已经生成的素材不倒改。MCP 也可显式传 profile 与 rate。旧媒体工作台自动播报读取同一浏览器偏好，使用相同摘要和音频处理链路。

官方音色说明：https://www.alibabacloud.com/help/en/model-studio/omni-voice-list

## 实现入口

frontend/src/Choice.tsx、ScrollPane.tsx、AnswerView.tsx、Suggestions.tsx：自绘控件与呈现。
frontend/src/App.tsx、Traffic.tsx、Orb.tsx、device.ts、style.css：首页、状态与音频驱动。
media/speech-style.mjs、providers.mjs、processor.mjs、service.mjs、tools.mjs：摘要、音色、语速及音频素材。
src/dashboard.mjs：实际可查询功能；src/agent-web.mjs：网页答复风格。
