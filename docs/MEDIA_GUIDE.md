# 媒体功能使用说明

当前版本保留图片理解、单次拍照和独立连续语音；后台摄像头监测按任务执行并生成图文记录。视频通话、画面指令自动执行、视频文件上传和首帧分析已移除。

## 启动网页助手

先用 Ctrl+C 退出旧服务，在项目根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-agent.ps1 --web
```

脚本自动查找 Node，支持本机缓存运行时，不要求 `node` 已加入 PATH。输入设备密码，或回车跳过设备连接。打开输出的完整链接即可使用，不需要同时启动 CLI Agent。页面令牌只保存在当前浏览器标签页的 sessionStorage，刷新可继续使用；服务重启后请打开新的完整链接。

只运行独立媒体服务时：`& $nodePath scripts/media.mjs`。设备问答和连续语音的 Agent 回复需要 `--web` 模式。

## 连续语音交流

新版主界面连接助手后自动开启语音待机，允许麦克风后说 **Hi Claude**，收到回应后再提问；无需先点击 AI 球体，也不会自动展开聊天文字。展开、收起聊天框共用同一语音会话，不重启采集。主界面可以关闭唤醒，关闭选择在本浏览器保留；若浏览器限制自动激活声音，点击主界面的“开启语音唤醒”重试。旧媒体工作台仍通过“语音待机”按钮开启。声纹模型和同人校验已移除，唤醒后任何人都可以继续发出需求；唤醒句本身仍不执行其中附带的指令。

麦克风与模型并行准备，回调先于音频连接安装。首次约 1.5 秒提交，之后每秒提交最多 6 秒的重叠窗口；窗口没有计划内的采集空挡。启动等待和推理等待期间的音频进入内存队列，按 120 秒待处理音频预算限流，超限明确报错并结束会话，不静默丢弃窗口。重叠窗口的重复部分也计入预算。唤醒成功时丢弃重复唤醒窗口，但拼接保留已提交窗口末尾之后的声音，不重复或遗漏切换期间的采样。

本地 Sherpa-ONNX 关键词阈值为 0.10、增强参数为 5；未命中时使用本机 SenseVoice 匹配有限发音变体。没有声纹提取、注册、同人匹配或补充样本要求。未唤醒声音不会提交云端 ASR。唤醒后两分钟没有接受到新片段需要重新唤醒，说“结束对话”或“再见”回到待机。

浏览器请求回声消除，但关闭自动增益和浏览器噪声抑制，避免多层处理叠加。收到的 WAV 由本地 voice_denoise.py 做一次温和的谱域降噪，减弱低频嗡声和稳定底噪，不提升音量。降噪不具备目标人声分离能力，不能把另一人的清晰讲话视为普通底噪消除。

唤醒后的断句保留约 0.6 秒预录，音量连续超过门限 0.12 秒后触发，约 0.9 秒静音后结束，最长约 25 秒；取消原来的 5 秒硬切。最长片段上限保护请求体和内存，并非停止麦克风。超过 25 秒仍分成独立请求，尚无跨段语义合并。能量判定不等于神经网络人声 VAD。

模型请求和语音合成等待期间继续收音；只在实际播放及之后约 0.2～0.25 秒跳过语音判定，防止播报自己触发，不支持语音打断。转写后展示用户原话，回答文字在对应音频开始播放时显示；语音讲精简摘要，不逐段朗读完整屏幕文字；播报失败保留文字。音色 / 语速及自绘交互详见[界面与声音细化](UI_REFINEMENTS.md)。

MEDIA_VOICE_DIAGNOSTICS=1 时，本次会话收到的 input.wav、降噪后实际送 ASR 的 asr.wav 和 result.json 暂存在 .media-state/voice-diagnostics/<id>/，记录两份 WAV 的哈希、唤醒状态、耗时和转写。可在结束语音前对照；结束语音或正常退出服务会清理该服务创建的会话记录，不删除历史测试样本、监测报告或其他进程的记录。异常强杀可能留下记录。关闭诊断时音频仅作为内存缓存。前端未提交或播放期间跳过的样本不会出现在目录。

本地模型位于 .tools/voice/，安装命令：powershell -ExecutionPolicy Bypass -File scripts/setup-voice.ps1。安装器不再下载声纹模型，现存 speaker.onnx 未主动删除，也不再加载。

当前仍是连续采集、分段 WAV → 本地去噪 / 唤醒 → 云端 ASR → Agent → TTS。现用 Qwen-Omni chat/completions 适配器不是持续上传音频的 Realtime WebSocket；真正流式 ASR 需要单独的实时接口接入，不能只修改 stream=true。详细变更和验证见 [语音链路调整](VOICE_PIPELINE.md)。

## 单次拍照

点击摄像头按钮后，先查看用途和范围；确认后才打开摄像头，按快门拍摄一张，随即释放摄像头。图片作为附件，可补充问题后发送。Agent 请求拍照时，也必须显示这个确认界面，不能自行拍摄。

单次拍照不录音、不持续监测。照片保存在 `.media-state/assets/`，作为当前对话素材使用；连续语音不会将摄像头画面作为输入，也不会识别纸条自动执行指令。

## 后台摄像头监测

可以在聊天中提出需求，也可以点击侧栏“安排摄像头监测”。例如：

> 观察门口是否有人经过，持续5分钟，每5秒采样，需要总结。

若只说“帮我监控视频画面”，助手应先询问具体观察什么、持续多久、是否需要总结，不直接启动摄像头。

确定需求后生成计划卡，明确显示：

- 监测目标。
- 监测时长（30秒至60分钟）。
- 采样间隔（2至60秒）。
- 是否生成模型总结。
- 默认图文记录位置。

**点击计划卡“确认并开始”后才启动。** MCP 只提供生成计划的工具，不提供模型批准计划的工具。语音或文字中的“确认”也不替代网页确认按钮。

监测在后台使用摄像头，不使用麦克风；可以同时进行独立语音交流。画面只用于约定任务的观察，不执行画面中的指令。过程不逐帧刷入聊天框，只显示任务进度和记录入口。

达到时长自动结束；也可以点击“结束并保存记录”。页面关闭、断连、摄像头异常或服务退出会停止并保存已完成部分。中断不会自动重新打开摄像头，服务重启会将未结束记录标为中断。

默认保存到：

```text
reports/monitoring/<任务ID>/
  index.html     可独立打开的图文报告，图片内嵌
  report.md      Markdown过程记录
  report.json    任务、时间、观察和状态的结构化记录
  images/        关键画面，最多50张，保留首帧
```

侧栏可下载图文报告。所有采样观察都有时间记录；关键画面按观察变化和周期保存。总结只依据已记录证据，采样之间可能遗漏事件，不等同于完整视频录像。模型总结失败时仍保留过程与图片，并明确标记未完成总结。

记录是本地普通文件，不加密、不自动删除；已加入 Git 忽略。可通过后端 `MEDIA_REPORT_DIR` 改变默认位置，网页不提供任意文件路径输入。任务计划10分钟内有效，过期后需重新生成。

## 界面

主界面只保留对话、图片／音频附件、单次拍照、连续语音和监测任务／结果。移除了“设置与素材”的开发调试界面。偏好设置仅控制是否朗读文字聊天答复；语音聊天始终播报。已适配桌面与手机布局，并提供轻量状态动效和减少动效设置适配。

## 模型与音色

DeepSeek 负责 Agent 决策，Qwen3-Omni-Flash 负责语音转写、图片理解、总结和语音生成。Key 分别保存在根目录 `credentials-agent.json`、`credentials-media.json`，使用 Windows DPAPI 加密。

当前默认音色 **Cherry**，后续在后端 `.env` 设置 `MEDIA_TTS_VOICE` 即可切换，重启服务生效。媒体凭据配置命令：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/configure-media.ps1
```

媒体 Key 只由媒体服务读取，不传给 MCP 子进程和 Agent 决策模型。语音问答的文字进入原有会话、任务和日志；原始连续语音只在内存中处理。问答的临时播报音频播放后删除。监测的关键画面按已确认计划保存并发送到视觉模型。

## 保留的CLI与工具

CLI保留 `/media`、`/listen 秒数`、`/voice on|off`、`/image 文件路径`、`/audio 文件路径`、`/speak 文字`、`/stop`。`/video` 已移除。命令行的 `/listen` 是固定时长录音，连续交流在网页开启。

当前13个媒体工具：`media_status`、`media_list_assets`、`media_record_audio`、`media_capture_photo`、`media_normalize_audio`、`media_transcribe`、`media_analyze_image`、`media_synthesize_speech`、`media_play_audio`、`media_stop_audio`、`media_prepare_monitor`、`media_monitor_status`、`media_stop_monitor`。

网页上传只接受 JPEG／PNG 和 PCM16 WAV，最大16MiB。FFmpeg 已安装在 `.tools/ffmpeg/ffmpeg.exe`，用于导入音频重采样；实时语音和摄像头监测不依赖 FFmpeg。

- `node scripts/media-ui-smoke.mjs`：使用本机 bundled Playwright + Chrome、假摄像头／麦克风检查桌面、手机、拍照确认、连续两轮语音、监测审核与报告下载，不使用真实硬件。
- `node scripts/media-workflow-live-smoke.mjs`：真实 DeepSeek／Qwen 流程验证，音频与画面全部生成，不访问真实设备。

新验证结果见 `docs/testing/MEDIA_TEST_RESULTS.md`。旧的视频通话、首帧测试报告仅保留为历史记录，不代表当前功能。
